# zhhz v0.7.8

**Distribution focus release.** The conversion engine from v0.7.7 is
now packaged for Node.js / browsers via `npm install zhhz`. Compiled
to WebAssembly with `wasm-bindgen`; OpenCC dictionaries baked into
the `.wasm` so the package is fully self-contained.

**Live**: <https://zhhz.ljh.sh/> (Jekyll site, 8 pages).

## Added

### npm package (`npm install zhhz`)

The same conversion engine compiled to WebAssembly, exposed to
JavaScript via `wasm-bindgen`. The conversion core in `src/engine.rs`
is unchanged — output is byte-identical to the CLI on every config.

- `convert(text, config)` — one-shot conversion across all 16 OpenCC configs.
- `convert_with_custom(text, config, entries)` — custom words injected
  at the highest priority. `entries` accepts **both** array form
  (`[["软件","軟體"]]`) and string form (`"软件 軟體|..."`, opencc-js
  `DictLike` compat).
- `detect(text)` — script-variant detection (`cn-s` / `cn-t` / `cn-tw` /
  `cn-hk` / `jp-n` / `jp-t`) returning `{ region, confidence }` (0–100).
  **Unique to zhhz** — opencc-js has no equivalent.
- `listConfigs()` / `listLocales()` — introspection.
- `configForRegionPair(from, to)` — resolve a semantic region pair to
  the right OpenCC config name (e.g. `(cn-s, cn-tw) → "s2twp"`).
- `new Converter(config)` — reusable factory instance with `.convert` /
  `.convertWithCustom` / `.withCustom` / `.config`.
- `Converter.forRegion(from, to)` — build a Converter from semantic
  region flags (mirrors the CLI's `--from` / `--to`).

### Documentation

- `docs/npm.md` — full npm reference (install, ESM/CJS, configs table,
  custom-words examples, detection, introspection, semantic regions,
  API-comparison table vs opencc-js).
- `examples/node-usage/` — runnable Node.js smoke (24 assertions
  exercising every exported API; `cd examples/node-usage && npm start`).

### CI

- `.github/workflows/wasm.yml` extended:
  - **wasm-pack pinned** to `v0.13.0` via `WASM_PACK_VERSION` so future
    upstream releases can't silently change the published artifact.
  - **`publish-dryrun` job** gated on `workflow_dispatch` exercises
    the bundler build + `npm pack --dry-run` + smoke import. Surfaces
    missing `NPM_TOKEN` immediately instead of silently failing on tag
    push.
  - **Smoke test expanded** from 4 cases to 24, covering every exported
    API end-to-end.

## Changed

- `src/wasm.rs` — gained `Converter` class, `listConfigs` / `listLocales`
  / `configForRegionPair`, and string-form custom-dict parsing. All
  additions are `#[cfg(feature = "wasm")]`-gated and only touch the wasm
  path; the native CLI / Rust consumer path (engine.rs, dict.rs,
  detect.rs) is unchanged.
- `convert_with_custom`'s `entries` parameter changed from
  `Vec<JsValue>` to `JsValue` (a single array of pairs). This is more
  ergonomic for TypeScript consumers and matches opencc-js's
  convention. Old callers that passed a flat array of pairs continue to
  work without change.

## Internal

- `.gitignore` — `pkg/` and `pkg-npm/` added so locally-built
  `wasm-pack` output never gets tracked.

## Compatibility

- **CLI**: drop-in. Same args, same output.
- **Rust library**: unchanged. `Converter::new`, `Converter::with_custom`,
  `convert(text) -> String`, `detect_text(text)`, `Detection` all behave
  identically to v0.7.7.
- **Native test speed**: `cargo test --release --locked` wall-time is
  unchanged. The wasm feature is opt-in and adds zero overhead to the
  native build (warm-cache run: 1.81 s vs v0.7.7 baseline 2.06 s, both
  well inside noise).
- **27 lib unit tests + 7 convert + 7 context + 1 doctest = 42 pass**
  (matches `changelog/v0.7.8.test.md`).

## Install

```sh
# npm (new)
npm install zhhz

# Cargo (unchanged)
cargo install zhhz --version 0.7.8

# Binary (unchanged)
curl -L https://github.com/ljh-sh/zhhz/releases/latest/download/zhhz-x86_64-unknown-linux-musl.tar.xz | tar xJ -
```

## What didn't ship

- Async / streaming API (deferred — WASM string boundary doesn't
  stream cleanly).
- napi-rs native binding (deferred — revisit only if benchmarks demand
  it).
- Per-platform prebuilds (`.node` binaries; same blocker as above).
- Replacing `convert_with_custom`'s array-pair shape (deferred; the
  current shape works).
