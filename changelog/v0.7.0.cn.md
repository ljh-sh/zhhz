# zhhz v0.7.0

## 故事

到 v0.6.0 为止，zhhz 对比的是 **opencc 1.2.0**（10 MB 中文 约 390 MB/s）。
v0.6.0 跑到 501 MB/s，我们宣布胜利。

然后有人 `brew install opencc`，拿到的却是 **opencc 1.3.1** ——
内置 marisa-trie，**realistic 中文跑到 ~65 MB/s**（同样的硬件比 1.2.0
快 ~6.5×）。我们的 501 MB/s 一下子看起来完全不一样：realistic 中文才是
实际工作负载，而我们只到 **opencc 1.3.1 的 0.50×**，不是 1.29×。

这个版本发布了 n-gram 功能，但**把性能工作延后** —— v0.7 → v0.8
的拆分是为了把 ngram 发出去而不让吞吐退步。性能补丁在 v0.7.1 /
v0.7.2 / v0.7.3 / v0.7.4 / v0.7.5 落地，最后**realistic 上达到
opencc 1.3.1 的 1.16×，真实语料上领先 7-12%**。

## Bench (10 MB 中文, Apple Silicon, release)

| 模式      | MB/s    | × opencc 1.3.1 |
| --------- | ------: | -------------: |
| fast      | 28.5    | **0.50×** (输) |
| bigram    | 21.7    | 0.33×          |
| trigram   | 21.5    | 0.33×          |
| opencc 1.3.1 | 65.7 | 1.00× (baseline) |

fast 路径的 0.50× 差距是 v0.7.1+ 性能补丁的目标。

## 新增

- **bigram / trigram 消歧** via `NgramModel` + `NgramMode::{Bigram, Trigram}`（CLI flags `--bigram` / `--trigram` / `--fast`）
- **ARPA 模型加载器**（`2gram.arpa` / `3gram.arpa`；未随包发布，见 ljh-sh/ngram-exp）
- **`Dict::longest_prefix_multi`** 给消歧路径用；默认 `Dict::longest_prefix` 保持零分配的 single-value 路径
- **Patch overlay**（`data/dictionary_patches/STPhrases.multi-value.tsv`）把单值条目升级成多值，无需 fork 上游 data 目录
- **10 个 context 回归测试** 覆盖 齣/出 消歧 + 2 个已知限制 + 1 个自定义词典变通

## 延期到 v0.7.1+ / v0.8

- `--report <PATH>` TSV sidecar（zhhz#15）
- `Converter::convert_with_report` / `scan_ambiguous`
- `AmbiguousDecision` struct
- 全部性能补丁（在 v0.7.1 → v0.7.5 落地）

## 兼容性

- 公开 API：`Converter::convert(&str) -> String` 不变
- CLI：现有 flags 不变；新增 `--bigram` / `--trigram` / `--fast`
- 数据：现有 `data/dictionary/` 不变；新增 `data/dictionary_patches/STPhrases.multi-value.tsv` 覆盖层
- WASM 构建：不受影响
- 输出与 v0.6.0 在两者都实现的每个 config 上字节完全一致

## 安装

```bash
cargo install zhhz --version 0.7.0
npm install zhhz@0.7.0
```
