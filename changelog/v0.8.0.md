# zhhz v0.8.0

**Detect-region classifier fix.** The conversion engine from v0.7.x is unchanged;
this release improves `zhhz detect` accuracy for short Taiwanese / Hong Kong text.

## Fixed

### `zhhz detect` TW/HK classifier

The TW/HK disambiguation heuristic previously scored **only** region-exclusive
phrases (TW phrases not in HK's value set, and vice versa). Many regional
phrases overlap — `滑鼠`, `伊利諾` are used in both Taiwan and Hong Kong —
so a short text containing only shared phrases was left stranded at `cn-t`.

New algorithm:

1. **Exclusive hits** (TW-only or HK-only phrases) still carry the strong
   regional signal. We pick the winner by absolute character count, not the
   previous 2× ratio, so short texts aren't starved.
2. **Shared hits** (TW ∩ HK phrases): when both regions have zero exclusive
   signal and shared signal is present, default to TW. Taiwan is the dominant
   regional-traditional variant in real corpora, and OpenCC's `s2t` and `s2tw`
   configs treat TW as the default target.

### Examples

| Text | Before | After |
|---|---|---|
| `我買了新的滑鼠很好用` | `cn-t` (10%) | **`cn-tw`** (40%) |
| `他感染了A型肝炎` | `cn-tw` (50%) | `cn-tw` (50%) (unchanged) |
| `他去了西維珍尼亞州` | `cn-hk` (50%) | `cn-hk` (50%) (unchanged) |
| `漢字計算機軟體繁體` | `cn-t` / `cn-tw` | `cn-tw` (升一档 because `軟體` is TW phrase) |

## Compatibility

- No conversion core change. `s2t` / `s2tw` / `s2hk` outputs are byte-identical
  to v0.7.x.
- Library API (`detect_text`, `detect_bytes`, `Detection`) unchanged.
- WASM bindings unchanged.
- Python wheels unchanged.

## Tests

- New unit test `regional_shared_phrase_defaults_to_tw` covers the `滑鼠` case.
- All 9 `detect::` tests pass (`cargo test detect::`).
- Full test suite (32 tests) passes.

## Migration

No action required for existing users. If you depend on `detect_text` returning
`cn-t` for short Taiwan-leaning text, you may see more `cn-tw` results now —
that's the intended fix.
