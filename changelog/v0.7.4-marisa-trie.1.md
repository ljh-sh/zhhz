# zhhz v0.7.4-marisa-trie.1

**Status: SHELVED.** This release is a technical-route exploration,
not a recommended release. The `v0.7.5` release on `release/v0.7.5`
is the current recommended version.

## What this is

A pure-Rust port of marisa-trie ([`rsmarisa`](https://crates.io/crates/rsmarisa))
integrated into zhhz as an **opt-in feature flag** (`--features marisa`).
The trie stores **keys only** (UTF-8 bytes); values are kept in a
parallel `Vec<Values>` indexed by `agent.key().id()` — the same
design OpenCC uses for its `.ocd2` marisa-trie format.

This was the **O** arm of the Q/M/O decision tree ([zhhz#26](https://github.com/ljh-sh/zhhz/issues/26)).

## Bench result (apples-to-apples, in-process 20 inner + 3 warmup)

| corpus | v0.7.5 (char-trie) | v0.7.4-marisa-trie.1 | Δ |
|--|--:|--:|--:|
| realistic-repeat fast | 75.17 | 73.12 | -2.7 % |
| realistic trigram | 33.59 | 32.66 | -2.8 % |
| classical fast | 41.26 | 41.00 | -0.6 % |
| classical trigram | 35.01 | 33.52 | -4.3 % |
| code fast | 67.83 | 68.16 | +0.5 % |
| news fast | 32.50 | 33.52 | +3.1 % |

No consistent win. Within ±3 % noise on all corpora.

## Decision

**Closed without merging to main.** See
[zhhz#33](https://github.com/ljh-sh/zhhz/issues/33) for the full
decision record and
[zhhz#34 retrospective](https://github.com/ljh-sh/zhhz/issues/34)
for the v0.7.x perf story.

The sample-based profile (zhhz#32) revealed that zhhz is already
**CPU-faster than opencc on every corpus** (133 MB/s vs opencc's 67
on realistic-var; 176 vs 141 on realistic-repeat). The wall gap is
**cache miss + allocator pressure**, not trie structure. Swapping in
marisa doesn't fix either.

## What's in this branch

- `src/dict_marisa.rs` — `MarisaDict` (190 lines) implementing the
  same `longest_prefix` / `longest_prefix_multi` API as `Dict`.
- `Cargo.toml` — `rsmarisa = { version = "0.4.2", default-features = false, optional = true }`,
  `marisa = ["dep:rsmarisa"]` feature flag.
- `src/lib.rs` — type-alias swap behind feature flag (`Dict` is
  `MarisaDict` when feature on).
- `examples/perf_only.rs` — in-process zhhz convert timer (also on
  main).
- `scripts/bench-apples.sh` — apples-to-apples bench runner.
- `scripts/bench-fast.sh` — fast-only bench runner (added later).

## Build / use

```bash
# Without marisa (default — works on the pinned toolchain):
cargo build --release

# With marisa (requires rustc ≥ 1.86 for edition2024 support):
cargo build --release --features marisa

# Run bench:
cargo run --release --example bench_perf
```

## Permanent home

Branch `v0.7.4-marisa-trie` lives **permanently on origin** as a
reference implementation. The implementation is **not recommended for
production use** — use `release/v0.7.5` instead.

If you want to verify the experiment yourself: clone, check out
`v0.7.4-marisa-trie`, run `cargo run --release --example bench_perf`
with rustc ≥ 1.86.
