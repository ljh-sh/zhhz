# v0.4.0

AI-agent positioning, a smarter `zhhz detect`, and auto-detect conversion to Simplified.

## Added

- **`zhhz detect` TW/HK classifier tuning.** The signature set is now the
  **region-exclusive** phrases (TW values that are not in HK's value set, and
  vice versa). Many regional phrases overlap on short forms that are used in
  both regions (`滑鼠`, `伊利諾`), so a single boolean hit produces false
  positives; the exclusive set disambiguates and longer matches carry more
  weight via the summed-character scoring. `滑鼠與電腦` (shared `滑鼠`
  only) → `cn-t`; `他感染了A型肝炎` (TW-exclusive) → `cn-tw`;
  `他去了西維珍尼亞州` (HK-exclusive) → `cn-hk`.
- **`--auto`**: detect each input's script variant and convert it to
  Simplified (`cn-s`). Default target is Simplified because most agents
  want normalised text; use `--from` / `--to` for any other target. Japanese
  input runs a 2-stage pipeline (`jp2t` then `t2s`). `zhhz --auto` on
  stdin, or `zhhz --auto file.txt`, or in batch.
- **chardet-style batch input for `convert`**: positional `<files>...`
  (directories walked recursively, sorted, regular files only), `-` for
  stdin content, `--files-from <PATH|->` to read a newline-separated list
  of paths from a file or stdin, and `-0` / `--null` for NUL-separated
  lists. The same pattern `zhhz detect` uses.
- README (en + cn): a new "Designed for AI agents" section that makes
  the tool's intended consumer explicit — no TUI, no progress bars,
  stdin / stdout friendly, stable / predictable output, chardet-style
  batch input, single self-contained binary.
- `docs/experience.md`: an article about building `zhhz` as a tool for
  AI agents. Covers the self-contained binary rationale, the opencc-as-
  standard correctness discipline, the `build.rs` that reproduces
  OpenCC's generated dictionaries, the `zhhz detect` feature, packaging
  (signing, scorecard, crates.io), and the parity harness as the
  correctness gate.

## Notes

- Engine (conversion core) unchanged. Parity vs opencc 1.2.0 unchanged
  at 538/538 supported-config cases.
- `zhhz detect` parity is unchanged; only the classification quality on
  multi-region text improves.
- Library API: no breaking changes.
- Binary size: **1.7 MB** (v0.3.0 was 1.7 MB; the new features are
  CLI-only logic and small in-memory signature sets).
