# v0.3.0

`zhhz detect` — script-variant detection, mirroring `chardet`'s design.

## Added

- **`zhhz detect <files>...`** subcommand that identifies the script variant
  (`cn-s` / `cn-t` / `cn-tw` / `cn-hk` / `jp-n` / `jp-t` / `unknown`) of Chinese
  text. Mirrors `chardet`'s CLI design one-to-one:
  - `<files>...` to detect each path
  - `-` (or no args) to detect content piped on stdin, with the path reported as `-`
  - `--files-from <PATH|->` to read a newline-separated list of paths from a file or stdin
  - `-0` / `--null` for NUL-separated lists
  - Recursive directory walking
- **Output**: TSV, one line per input, `<region>\t<confidence>\t<path>`.
  Confidence is 0–100 (the winning region's share of signature characters).
- **Library API**: `zhhz::detect_text(&str) -> Option<Detection>` and
  `zhhz::detect_bytes(&[u8]) -> Option<Detection>` for programmatic use.
- **Classifier** derives per-region signature character sets from the vendored
  OpenCC data at runtime (no new dependencies, stays in sync with the data):
  - `cn-s`: `STCharacters` keys where the first value differs from the key
  - `cn-t`: `TSCharacters` keys where the first value differs
  - `cn-tw`: `TWVariants` keys
  - `cn-hk`: `HKVariants` keys
  - `jp-n`: `JPShinjitaiCharacters` keys (shinjitai / new-form)
  - `jp-t`: `JPShinjitaiCharacters` first values (kyūjitai / old-form)
- Hiragana/Katakana presence routes to the JP branch; otherwise the Chinese
  branch with a TW/HK upgrade heuristic.
- README: added OpenSSF Scorecard and Parity badges.

## Notes

- Engine + conversion API unchanged; parity vs opencc 1.2.0 still 538/538
  (14 of 16 configs byte-for-byte; `s2hkp`/`hk2sp` still 1.2.0-unsupported).
- Binary size: **1.7 MB** (v0.2.0 was 1.6 MB; the +~100 KB is the detect
  feature, classifier tables, and signature sets).
