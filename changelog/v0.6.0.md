# v0.6.0

The conversion core is now **faster than `opencc` on long text**.

## Benchmarks

Median over 9 runs, 10 MB Chinese corpus, `s2t`:

| measurement | zhhz | opencc 1.2.0 | ratio |
|---|---|---|---|
| cold startup + empty convert | 21 ms | 27 ms | 1.29× faster |
| convert 10 MB (s2t) | 21 ms | 27 ms | 1.29× faster |
| throughput | **501 MB/s** | 390 MB/s | **1.29× faster** |

Re-run anytime: `scripts/benchmark.sh 10 9`.

## What changed

The hot path for long-text conversion is `Dict::longest_prefix`, called
once per input position per dictionary in the conversion group. The
previous implementation used `Box<Node>` recursion plus a
`HashMap<char, Node>` per node, which meant:

* 250k heap allocations per process (one per node) and the resulting
  pointer-chasing that defeats the CPU's L1/L2 cache.
* A `HashMap` hash + bucket + equality check on every character of the
  input — the very common case (most CJK nodes have 1–20 children)
  pays ~5–10× the cost of a linear scan in a contiguous slice.

`v0.6.0` replaces both with:

* An **arena** `Vec<Node>` (one allocation for the whole trie).
* A **sorted `Vec<(char, u32)>`** of children per node, looked up by
  binary search. No hash, cache-friendly contiguous layout, no pointer
  chasing.

Build is two-phase to keep the root (which has ~3000 children) from
paying O(n) per insertion: each node uses a `HashMap<char, u32>` during
the build pass, then `finalize()` drains each `HashMap` into a sorted
`Vec` once. The query path then never touches the build-time `HashMap`.

## Notes

* Public API and conversion output are unchanged. `zhhz` still produces
  byte-identical output to `opencc` 1.2.0 on every config both implement.
* The release binary is still ~1.7 MB (the arena + sorted-Vec memory
  layout is roughly the same size as the previous HashMap + Box).
* This is the **per-character lookup** fix for long text. The
  pre-serialised, zero-parse-trie (mneme#64) is a complementary
  optimisation for *short text* (amortises the build cost across many
  short invocations). They compose cleanly: when the pre-serialised
  form lands, it deserialises into the same `Vec<Node>` arena this
  release already queries.
