# zhhz v0.7.9

**CI plumbing fix.** No user-visible change to the npm tarball
(same 616 kB, same Rust core, same WASM API).

## Fixed

- `.github/workflows/wasm.yml` — the `Publish to npm` step now
  writes the token via `npm config set //registry.npmjs.org/:_authToken`
  in addition to setting the `NODE_AUTH_TOKEN` env var. On the
  ubuntu-latest runner, `npm whoami` was returning ENEEDAUTH with
  env-var-only auth (likely an npm 10.x auth-precedence quirk reading
  a stale source before the env var). With both set, the
  `whoami` step prints `edwinjhlee` and `npm publish` proceeds.
  Two debug `echo` lines print the token length + first 8 chars
  so future "ENEEDAUTH with a good token" failures are diagnosable
  in CI logs without exposing the full secret.

## Internal

- Bumped `Cargo.toml` to `0.7.9` so the `v*` tag can re-trigger
  the publish job cleanly. (`npm publish` rejects re-publishing
  the same version.)
- `Cargo.lock` regenerated for the new version.
