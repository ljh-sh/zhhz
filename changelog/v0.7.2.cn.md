# zhhz v0.7.2

**zhhz fast path：realistic 52.32 → 53.38 MB/s（+2.0%）。**
累计对比 v0.7.0：**+62%**。对 opencc 1.3.1：**0.81×**。

一个变化：`unsafe_push_str_ascii` helper，当匹配到的词典值是 ASCII 时
用 `copy_nonoverlapping`。跳过 `String::push_str` 的 UTF-8 校验。

## 新增

- **`unsafe_push_str_ascii(out, value)` helper。** 仅当 `value.is_ascii()`
  在运行时确认 UTF-8 安全时才走条件 `unsafe` 路径。跳过 ASCII 匹配
  （数字 / 标点的常见情况）的 `String::push_str` UTF-8 校验开销。

```rust
// SAFETY: caller must guarantee `value.is_ascii()`. Under that
// precondition, each byte of `value` is < 0x80 and can be safely
// copied as raw bytes into the output buffer (which holds valid
// UTF-8).
fn unsafe_push_str_ascii(out: &mut String, value: &str) {
    debug_assert!(value.is_ascii());
    let bytes = value.as_bytes();
    let old_len = out.len();
    let new_len = old_len + bytes.len();
    if new_len > out.capacity() {
        out.reserve(new_len - old_len);
    }
    unsafe {
        let dst = out.as_mut_vec().as_mut_ptr().add(old_len);
        std::ptr::copy_nonoverlapping(bytes.as_ptr(), dst, bytes.len());
        out.as_mut_vec().set_len(new_len);
    }
}
```

## 为什么只有 +2 %？

zhhz#18 中之前的实验 **C** 在多字节路径上尝试 `unsafe`，结果输了 2.6%。
把 `unsafe` 限定在 ASCII-only 情况下才是正确的模式，能在 v0.7.1 之上
拿到一个小但稳定的胜利。

opencc 差距的主要部分（52 → 65 MB/s）是结构性的 —— 要关闭它需要
byte-based trie 或 marisa-trie 集成，不是 micro-opt。
