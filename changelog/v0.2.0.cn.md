# v0.2.0

面向多地的简繁转换 + 真正的并行测试门槛。

## 新增

- **`--from <REGION> --to <REGION>`** 语义化 CLI。使用短区域代码取代晦涩的配置名：`cn-s`、`cn-t`、`cn-tw`、`cn-hk`、`jp-t`、`jp-n`。例如 `echo 汉字 | zhhz --from cn-s --to cn-tw`。区域对自动映射到对应的 OpenCC 配置（如 `cn-s → cn-tw` → `s2twp`，应用台湾短语）。与 `--config` 互斥。
- **`--list`** 现在显示区域代码与 from→to→配置 的映射表。
- **差异性测试工具**（`examples/parity.rs`）：逐字节对比 `zhhz` 与 `opencc` CLI，覆盖全部 16 个内置配置。参考实现不支持的配置（如 `s2hkp`/`hk2sp` 在 opencc 1.2.0 中缺失）归类为 *unsupported* 并跳过，不算失败。两者都支持的配置若不一致，退出码 1。
- **`scripts/build-reference-opencc.sh`**：从 `data/UPSTREAM` 钉住的 commit 构建 opencc 并正确安装（带 rpath），使 CI（以及开发者）能针对**使用相同数据**的参考运行差异性测试。
- **`Parity`** GitHub Actions 工作流：在每个 PR 中安装 cmake/g++、构建参考 opencc 并运行差异性测试。
- 区域解析与 `region_pair_config` API 在库中公开，便于 x-cmd `hanzi` 功能集成。

## 与系统 opencc 1.2.0 的并行测试结果

- **538 / 538** 双方都支持的用例逐字节一致（16 个配置中的 14 个：`s2t`、`t2s`、`s2tw`、`tw2s`、部分 `s2twp`/`tw2sp`、`s2hk`、`hk2s`、`t2tw`、`tw2t`、`t2hk`、`hk2t`、`t2jp`、`jp2t`）
- **78** 个用例因 opencc 1.2.0 不支持 `s2hkp`/`hk2sp` 而跳过（这两个配置是 opencc 1.3 才加入的，zhhz 已经覆盖）
- **8** 个 `s2twp`/`tw2sp` 不匹配，全部可由 vendored 数据（cf0e4b6）比 1.2.0 较新解释——例如 `B超 → 超音波`、`密歇根州 → 密西根州`、`西弗吉尼亞 → 西維吉尼亞`。这些是**数据版本差异，不是引擎 bug**：新的 `Parity` CI 工作流会从 `data/UPSTREAM` 构建 opencc，预计将不匹配降到 0。

## 备注

- 仍支持 `--config`（向后兼容）；多地场景建议使用 `--from`/`--to`
- 转换引擎代码无改动；并行测试证实 v0.1 引擎已正确。v0.2 是可用性 + 可测试性 发布
