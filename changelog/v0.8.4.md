# zhhz v0.8.4

**ClusterFuzzLite migration.** No user-visible change to the Rust core,
npm tarball, or WASM API. Same 616 kB binary.

## Changed

- **OSS-Fuzz → ClusterFuzzLite.** google/oss-fuzz#16131 was closed by
  Google because zhhz doesn't yet meet the OSS-Fuzz adoption bar. Following
  the reviewer's suggestion, we switch to ClusterFuzzLite, which runs
  entirely in GH Actions and provides the same libFuzzer + sanitizer
  coverage without the adoption hurdle.
- `oss-fuzz/` subtree removed. `projects/zhhz/` on google/oss-fuzz
  is no longer relevant (ClusterFuzzLite is the canonical home now).
- Re-evaluate OSS-Fuzz submission when zhhz has wider adoption.

## Added

- `.clusterfuzzlite/` subtree (mirrors what would have been
  `projects/zhhz/` on google/oss-fuzz):
  - `project.yaml` — `language: rust`
  - `Dockerfile` — `FROM gcr.io/oss-fuzz-base/base-builder-rust`,
    copies `build.sh` to `$SRC/build.sh` (ClusterFuzzLite compile
    wrapper's expected path)
  - `build.sh` — `cargo +nightly fuzz build --sanitizer=<s> --release`,
    then `cp $BIN_DIR/<target> $OUT/zhhz-fuzz-<target>`
- `.github/workflows/cflite-pr.yml` — code-change fuzzing on every PR,
  600s × sanitizer. Fails the PR if a crash is found.
- `.github/workflows/cflite-batch.yml` — 6h batch fuzzing schedule,
  3600s × sanitizer. Discovers deeper bugs that PR fuzzing misses.
- `.github/workflows/cflite-build.yml` — continuous build verification
  on every push to main.

## Dropped from ClusterFuzzLite matrix (deferred)

- **MSan** — the base image's rustc 1.99 nightly has a linking bug in
  `compiler_builtins` under `-Z build-std + -Zsanitizer=memory` that
  fails with "no group info for section". Re-enable when the
  ClusterFuzzLite base image is bumped past the bug. The standalone
  GH Actions fuzz workflow (`.github/workflows/fuzz.yml`) still runs
  MSan and is the place we look for use-of-uninitialized-value bugs.
- **UBSan** — rustc removed `-Z sanitizer=undefined` from accepted
  values after nightly ~2024-11. Re-enable when stable.

## Notes

- Two `fuzz` configurations now coexist:
  1. **`.github/workflows/fuzz.yml`** — standalone cargo-fuzz driven
     directly. Runs ASan + MSan on nightly/weekly schedule. 4 jobs.
     This is the "always-on" smoke test.
  2. **`.github/workflows/cflite-*.yml`** — ClusterFuzzLite driven
     via Google's GitHub Actions. PR fuzzing on every PR + batch
     fuzzing every 6h + continuous builds. ASan only for now.
- Both can find bugs; the standalone workflow has lower latency
  (60s nightly run surfaces issues same-day) while ClusterFuzzLite
  has higher coverage (PR-level + 6h batch).
