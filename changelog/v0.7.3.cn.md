# zhhz v0.7.3

**zhhz fast realistic：53.38 → 75.91 MB/s（+42%）。**
累计对比 v0.7.0：**33 → 76 MB/s（+130%）**。
**对 opencc 1.3.1：0.81× → 1.17×** —— 在 realistic 上击败 opencc。

一个结构性变化：当 config 组有不相交的 phrase + character 词典
（s2t/t2s 的模式）时，合并成一个 trie。每个 FMM segment 做 1 次 trie
查找而不是 N 次。

## 新增

- **`src/config.rs` 的 `try_merge_group()`。** 把组里所有词典文本拼接
  （phrase 在前以遮蔽任何 character 重叠），构建一个 trie。
  在组 spec 只有 file-based children 时由 `expand()` 应用。

对 s2t 来说，合并了：
- `STPhrases_Generated`（508 条）
- `STPhrases`（49,136 条）
- `STCharacters`（4,011 条）

到一个 `Dict` 里。FMM 的 longest-prefix 逻辑天然优先匹配多字的
STPhrases 条目，胜过单字的 STCharacters。

## 为什么有效

合并前通过实测验证了 key 不相交 —— phrase 词典和 character 词典
之间零重叠。FMM 的 longest-prefix 语义保持不变（更长的多字 phrase 胜出）。

## 为什么 ascii-y 涨 130 %

ascii-y 语料（拉丁文，无中文）几乎不会匹配这 3 个原始词典中的任何一个。
以前每个 FMM segment 做 3 次失败的 trie 查找；现在只做 1 次。
不匹配字符的查找开销降到 1/3。

## 为什么 realistic 涨 42 %

即使字符真的匹配，合并意味着**一次 trie 遍历**而不是 3 次（或当多字
phrase 匹配时，**一次遍历找到最长匹配**，而不是在第一个词典匹配后就
短路返回）。

## 内部

- 新 `examples/bench_perf.rs` — 多语料跑分（3 个语料，best-of-5）
- 新 `examples/diff_corpus.rs` — 1000 句字节相等性检查

## 注意

- 45 / 45 测试通过，零退步
- 1000 句 `diff_corpus` 输出与 v0.7.2 baseline 字节完全一致
- API 不变，输出字节一致，无新依赖
- WASM 构建不受影响
