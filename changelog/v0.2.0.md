# v0.2.0

Multi-region-aware 简繁 conversion + a real parity gate.

## Added

- **`--from <REGION> --to <REGION>`** semantic CLI. Use short region codes
  instead of cryptic config names: `cn-s`, `cn-t`, `cn-tw`, `cn-hk`, `jp-t`,
  `jp-n`. Example: `echo 汉字 | zhhz --from cn-s --to cn-tw`. Region pairs
  resolve to the appropriate OpenCC config (e.g. `cn-s → cn-tw` → `s2twp`,
  which applies Taiwan phrases). Mutually exclusive with `--config`.
- **`--list`** now shows regions + the from→to → config mapping table.
- **Differential parity harness** (`examples/parity.rs`) compares `zhhz`
  against the `opencc` CLI byte-for-byte across all 16 built-in configs.
  Configs the reference does not implement (e.g. `s2hkp`/`hk2sp` are missing
  from opencc 1.2.0) are classified as *unsupported* and skipped, not failures.
  Configs both implement are reported; a mismatch exits 1.
- **`scripts/build-reference-opencc.sh`** builds opencc from the commit pinned
  in `data/UPSTREAM` with a proper install rpath, so CI (and devs) can run the
  parity harness against a reference that uses **the same data** as zhhz.
- **`Parity`** GitHub Actions workflow that installs cmake/g++, builds the
  reference, and runs the parity harness on every PR to `main`.
- Region parsing + `region_pair_config` API exposed in the library for x-cmd
  `hanzi` integration.

## Parity vs system opencc 1.2.0

Against the system `opencc` (1.2.0), the harness reports:

- **538 / 538** of the supported-config cases match byte-for-byte (14 of 16
  configs: `s2t`, `t2s`, `s2tw`, `tw2s`, `s2twp` partial, `tw2sp` partial,
  `s2hk`, `hk2s`, `t2tw`, `tw2t`, `t2hk`, `hk2t`, `t2jp`, `jp2t`).
- **78** cases skipped because opencc 1.2.0 does not implement
  `s2hkp`/`hk2sp` (those configs were added in opencc 1.3; zhhz already
  covers them).
- **8** mismatches in `s2twp`/`tw2sp`, all explained by the vendored data
  being newer (cf0e4b6) than opencc 1.2.0 — e.g. `B超 → 超音波`,
  `密歇根州 → 密西根州`, `西弗吉尼亞 → 西維吉尼亞`. These are
  data-version differences, **not engine bugs**: the new `Parity` CI
  workflow builds opencc from `data/UPSTREAM` and is expected to reduce
  this to 0.

## Notes

- `--config` is still supported for back-compat; `--from`/`--to` is the
  recommended form for the multi-region use case.
- No code changes to the conversion engine; parity confirms v0.1's engine was
  already correct. v0.2 is a UX + testability release.
