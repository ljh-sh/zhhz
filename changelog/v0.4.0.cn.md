# v0.4.0

AI-agent 定位、更智能的 `zhhz detect`、以及自动检测后转为简体。

## 新增

- **`zhhz detect` TW/HK 分类器调优。** 签名集合改为**各地区独占**的短语
  （TW 的 value 中不在 HK value 集合的部分，反之亦然）。许多地区短语在
  短形上有两岸重合（`滑鼠`、`伊利諾` 两地都用），单次布尔命中会产生
  误报；独占集合消除歧义，且通过匹配字符总长让更长的匹配获得更高权重。
  `滑鼠與電腦`（只有共有的 `滑鼠`）→ `cn-t`；
  `他感染了A型肝炎`（TW 独占）→ `cn-tw`；
  `他去了西維珍尼亞州`（HK 独占）→ `cn-hk`。
- **`--auto`**：自动检测每个输入的简繁/地区变体并转为简体（`cn-s`）。默认
  目标是简体，因为大多数 agent 想要归一化文本；其他目标请用 `--from`/`--to`。
  日文输入走 2 段管道（`jp2t` 再 `t2s`）。`zhhz --auto` 可作用于 stdin、
  单个文件，或批量。
- **chardet 风格的批量输入**（用于 `convert`）：位置参数 `<files>...`
  （目录递归遍历、排序、只取常规文件），`-` 表示从 stdin 读**内容**，
  `--files-from <PATH|->` 从文件或 stdin 读换行分隔的路径列表，`-0` / `--null`
  为 NUL 分隔。与 `zhhz detect` 一致。
- README（中英）：新增 "Designed for AI agents" 章节，明确工具的目标用户
  ——无 TUI、无进度条、stdin/stdout 友好、稳定可预测、chardet 风格的批量
  输入、单一自包含二进制。
- `docs/experience.md`：关于把 `zhhz` 打造为 AI-agent 工具的文章。涵盖
  自包含二进制的设计理由、opencc 作为正确性标准、`build.rs` 重现
  OpenCC 生成的词典、`zhhz detect` 特性、打包（cosign、scorecard、crates.io），
  以及并行测试作为正确性门槛。

## 备注

- 转换引擎（核心）未变。与 opencc 1.2.0 的并行测试仍为 538/538。
- `zhhz detect` 的并行结果不变；仅在多地区文本上的分类质量提升。
- 库 API：无破坏性改动。
- 二进制体积：**1.7 MB**（v0.3.0 为 1.7 MB；新功能仅为 CLI 逻辑与
  较小的内存特征集合）。
