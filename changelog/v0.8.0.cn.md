# zhhz v0.8.0

**区域识别修复版**。转换核心 v0.7.x 完全不变；本版本只改进
`zhhz detect` 在短文本场景下的 TW/HK 区分准确率。

## 修复

### `zhhz detect` TW/HK 分类器

之前的 TW/HK 区分算法**只**统计区域**独有**短语 (TW 短语不在 HK 词集，反之亦然)。
但很多区域短语在两岸通用 —— `滑鼠`、`伊利諾` —— 仅含这些共享短语的
短文本会被卡在 `cn-t` 误判。

新算法：

1. **独占命中** (TW-only 或 HK-only 短语) 仍然是强信号。胜出按**绝对字符数**比较，
   不再使用原来的 2× 倍率，避免短文本被饿死。
2. **共享命中** (TW ∩ HK 短语)：当两边独占信号均为 0、共享信号 > 0 时，默认归为 TW。
   台湾繁体用法在实际语料中更普遍，且 OpenCC `s2t` / `s2tw` 配置也把 TW 作为默认目标。

### 示例

| 文本 | 修复前 | 修复后 |
|---|---|---|
| `我買了新的滑鼠很好用` | `cn-t` (10%) | **`cn-tw`** (40%) |
| `他感染了A型肝炎` | `cn-tw` (50%) | `cn-tw` (50%) (不变) |
| `他去了西維珍尼亞州` | `cn-hk` (50%) | `cn-hk` (50%) (不变) |
| `漢字計算機軟體繁體` | `cn-t` / `cn-tw` | `cn-tw` (含 `軟體` 升级) |

## 兼容性

- 转换核心未变。`s2t` / `s2tw` / `s2hk` 输出与 v0.7.x 完全一致。
- 库 API (`detect_text`, `detect_bytes`, `Detection`) 不变。
- WASM 绑定不变。
- Python wheels 不变。

## 测试

- 新单元测试 `regional_shared_phrase_defaults_to_tw` 覆盖 `滑鼠` 场景。
- `detect::` 9 个测试全部通过 (`cargo test detect::`)。
- 全量测试套件 (32 个) 通过。

## 升级

现有用户无需任何操作。如果你的代码依赖 `detect_text` 对短台湾繁体文本返回 `cn-t`，
现在会看到更多 `cn-tw` 结果 —— 这是预期修复。
