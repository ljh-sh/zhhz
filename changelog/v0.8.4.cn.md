# zhhz v0.8.4

**ClusterFuzzLite 迁移。** Rust 核心、npm 包、WASM API 无变化，二进制仍是 616 kB。

## 改动

- **OSS-Fuzz → ClusterFuzzLite。** google/oss-fuzz#16131 被 Google 关掉（zhhz 未达采用门槛）。按 reviewer 建议切到 ClusterFuzzLite，GH Actions 内置 libFuzzer + sanitizer 覆盖，没有采用门槛。
- 删除 `oss-fuzz/` 子树；`projects/zhhz/` on google/oss-fuzz 不再相关。
- 等 zhhz 进一步被采用后再考虑重新提交 OSS-Fuzz。

## 新增

- `.clusterfuzzlite/` 子树（替代 `projects/zhhz/` on google/oss-fuzz）：
  - `project.yaml` — `language: rust`
  - `Dockerfile` — `FROM gcr.io/oss-fuzz-base/base-builder-rust`，把 `build.sh` 复制到 `$SRC/build.sh`（ClusterFuzzLite compile wrapper 期望的位置）
  - `build.sh` — `cargo +nightly fuzz build --sanitizer=<s> --release`，再 `cp $BIN_DIR/<target> $OUT/zhhz-fuzz-<target>`
- `.github/workflows/cflite-pr.yml` — 每次 PR 都跑 code-change fuzzing，600s × sanitizer
- `.github/workflows/cflite-batch.yml` — 6h 周期 batch fuzzing，3600s × sanitizer
- `.github/workflows/cflite-build.yml` — 每次 push to main 都验证 build

## ClusterFuzzLite 矩阵中暂时排除

- **MSan** — base image 的 rustc 1.99 nightly 在 `-Z build-std + -Zsanitizer=memory` 链接 `compiler_builtins` 时有 bug（`no group info for section`）。等 ClusterFuzzLite base image 升级后再加。GH Actions 的 `.github/workflows/fuzz.yml` 仍跑 MSan，是我们找 use-of-uninitialized-value bug 的地方。
- **UBSan** — rustc 在 nightly ~2024-11 之后把 `-Z sanitizer=undefined` 从接受值里去掉。等稳定后再加。

## 备注

- 两套 fuzz 配置共存：
  1. **`.github/workflows/fuzz.yml`** — 直接 cargo-fuzz 驱动。ASan + MSan，nightly/weekly 跑。4 个 cell。是"always-on" smoke test。
  2. **`.github/workflows/cflite-*.yml`** — ClusterFuzzLite 通过 Google 官方 GH Actions 驱动。PR fuzzing + 6h batch fuzzing + continuous builds。目前只跑 ASan。
- 两者都能找 bug。standalone workflow 延迟低（60s nightly 跑当天就能发现），ClusterFuzzLite 覆盖深（PR 级 + 6h batch）。
