# zhhz v0.8.1

**`--auto` configurable target.** `--auto` previously always converted to
Simplified (`cn-s`). This release adds `--target <REGION>` so users can
route auto-detected input to any supported destination.

## Added

### `--target <REGION>` (with `--auto`)

```bash
# detect + convert to a chosen region
echo '我買了滑鼠' | zhhz --auto --target cn-t
echo '我买了鼠标' | zhhz --auto --target cn-tw

# default (cn-s) — unchanged
echo '我買了滑鼠' | zhhz --auto       # 我买了鼠标
```

**Supported `(from → target)` combinations** with `--auto`:

| target | from | path |
|---|---|---|
| `cn-s` (default) | `cn-s` | passthrough |
| `cn-s` | `cn-t` | `t2s` |
| `cn-s` | `cn-tw` | `tw2sp` (TW phrase-aware) |
| `cn-s` | `cn-hk` | `hk2sp` (HK phrase-aware) |
| `cn-s` | `jp-t` | `t2s` |
| `cn-s` | `jp-n` | `jp2t` → `t2s` |
| `cn-t` | `cn-s` | `s2t` |
| `cn-t` | `cn-t` | passthrough |
| `cn-t` | `jp-n` | `jp2t` |
| `cn-t` | `jp-t` | passthrough |

**Unsupported** combinations (e.g. `cn-tw → cn-t`, `cn-s → cn-tw`) emit a
clear error pointing the user to `--config + --from/--to`:

```
error: --auto does not support converting CnTw to CnT;
       use --config + --from/--to for that combination
```

The conversion core (16 OpenCC configs, byte-identical to v0.8.0) is
unchanged. The detect TW/HK tuning from v0.8.0 is unchanged.

## Validation rules

`--target` requires `--auto`. `--target` conflicts with `--to` (which is
the source-side `target` for explicit `--from/--to` routing, not the
auto-routing destination):

```bash
$ zhhz --target cn-t input.txt
error: --target requires --auto

$ zhhz --auto --target cn-t --to cn-tw input.txt
error: --target conflicts with --to (use --target with --auto only)
```
