# zhhz v0.7.4

**ASCII 开头文本最高快 5.5 倍**（ascii-y 77 → 192 MB/s）。
对混合 / 中文文本，性能与 v0.7.3 在噪声范围内一致。

在 FMM 循环里加了一个字节扫描透传：当 segment 以 ASCII 开头时，扫到
下一个非 ASCII 字节，然后整段 bulk-copy。中文开头的 segment 走原来的
char walk（在纯中文上避免逐字节扫描的开销）。

## 新增

- **FMM 循环的 SIMD 式 ASCII pass-through。** 当 segment 以 ASCII 开头
  （`bytes[0] < 0x80`）时，用 `find_non_ascii()` 扫到下一个非 ASCII 字节，
  用 `copy_nonoverlapping` 整段 bulk-copy ASCII 块（跳过 `String::push_str`
  的 UTF-8 校验）。中文开头的 segment 走 char walk。

`find_non_ascii()` 是个简单循环。真正的 SIMD 实现会用 `memchr::memchr3`
或 `safe_arch` 的 NEON/SSE2 intrinsics；这个简单循环够用，且改动小。

## 为什么 ascii-y 涨这么多

拉丁文几乎不会匹配任何中文词典。以前每个 ASCII 字节都要走
`char_indices()` + trie walk + 1 字节 push。现在整段 ASCII 在一次扫描里
找到，一次 `copy_nonoverlapping` 拷贝完成。10 MB 纯拉丁语料上，每字节
工作量降到 1/5。

## 为什么 realistic 退步 2 %

realistic 中文文本的 segment 都以非 ASCII 字节（多字节 UTF-8 lead）开头。
SIMD 路径的 `if bytes[0] < 0x80` 检查总为 false，所以会落到原来的
char walk —— 但多了一个分支检查，在热循环里消耗一点。这个退步在
v0.7.3 baseline 的噪声范围内。
