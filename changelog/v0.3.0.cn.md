# v0.3.0

`zhhz detect` —— 文体变体识别，镜像 `chardet` 的设计。

## 新增

- **`zhhz detect <files>...`** 子命令，识别文本的简繁/地区变体
  （`cn-s` / `cn-t` / `cn-tw` / `cn-hk` / `jp-n` / `jp-t` / `unknown`）。
  与 `chardet` 的 CLI 设计一一对应：
  - `<files>...` 检测每个路径
  - `-`（或不传参）从 stdin 读**内容**检测，路径报告为 `-`
  - `--files-from <PATH|->` 从文件/标准输入读换行分隔的路径列表
  - `-0` / `--null` 改为 NUL 分隔
  - 目录递归遍历
- **输出**：TSV，每行 `<region>\t<confidence>\t<path>`。
  置信度 0–100（获胜区域的特征字符占比）。
- **库 API**：`zhhz::detect_text(&str) -> Option<Detection>` 和
  `zhhz::detect_bytes(&[u8]) -> Option<Detection>`。
- **分类器**在运行时从 vendored OpenCC 数据派生每区域特征字符集
  （不引入新依赖，与数据自动同步）：
  - `cn-s`：`STCharacters` 中 key ≠ 首个 value 的键
  - `cn-t`：`TSCharacters` 中 key ≠ 首个 value 的键
  - `cn-tw`：`TWVariants` 的键
  - `cn-hk`：`HKVariants` 的键
  - `jp-n`：`JPShinjitaiCharacters` 的键（新字体）
  - `jp-t`：`JPShinjitaiCharacters` 首个 value（旧字体）
- 有平假名/片假名走 JP 分支；否则走中文分支（含 TW/HK 升级启发式）。
- README：加入 OpenSSF Scorecard 与 Parity 徽章。

## 备注

- 转换引擎与 API 未改动；与 opencc 1.2.0 并行测试仍为 538/538（14/16 配置逐字节一致；s2hkp/hk2sp 仍为 1.2.0 不支持）。
- 二进制体积：**1.7 MB**（v0.2.0 为 1.6 MB；+~100 KB 为 detect 特性、分类器表与特征集）。
