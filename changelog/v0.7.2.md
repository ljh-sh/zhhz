# zhhz v0.7.2

**zhhz fast path: 52.32 → 53.38 MB/s on realistic (+2.0 %).**
Cumulative vs v0.7.0: **+62 %**. vs OpenCC 1.3.1: **0.81×**.

One small change: `unsafe_push_str_ascii` helper that uses
`copy_nonoverlapping` when the matched dict value is ASCII. Skips
`String::push_str`'s UTF-8 validation pass.

## Added

- **`unsafe_push_str_ascii(out, value)` helper.** Conditional `unsafe`
  path used only when `value.is_ascii()` proves validity at runtime.
  Skips `String::push_str`'s UTF-8 validation pass for ASCII matches
  (the common case for digit/punctuation keys).

```rust
// SAFETY: caller must guarantee `value.is_ascii()`. Under that
// precondition, each byte of `value` is < 0x80 and can be safely
// copied as raw bytes into the output buffer (which holds valid
// UTF-8).
fn unsafe_push_str_ascii(out: &mut String, value: &str) {
    debug_assert!(value.is_ascii());
    let bytes = value.as_bytes();
    let old_len = out.len();
    let new_len = old_len + bytes.len();
    if new_len > out.capacity() {
        out.reserve(new_len - old_len);
    }
    unsafe {
        let dst = out.as_mut_vec().as_mut_ptr().add(old_len);
        std::ptr::copy_nonoverlapping(bytes.as_ptr(), dst, bytes.len());
        out.as_mut_vec().set_len(new_len);
    }
}
```

## Why only +2 %?

Earlier experiment **C** in zhhz#18 tried `unsafe` on the multi-byte
path and lost 2.6 %. Restricting `unsafe` to the ASCII-only case
is the right pattern, and gives a small but consistent win on top
of v0.7.1.

The bulk of the opencc gap (52 → 65 MB/s) is structural — closing
it requires a byte-based trie or marisa-trie integration, not
micro-opts.
