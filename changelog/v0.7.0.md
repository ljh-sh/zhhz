# zhhz v0.7.0

## Story

Up through v0.6.0, zhhz was benching against **opencc 1.2.0** (~390 MB/s
on 10 MB Chinese text). v0.6.0 hit 501 MB/s and we declared victory.

Then someone installed `brew install opencc` and got **opencc 1.3.1**
instead — which ships with a marisa-trie and runs at **~65 MB/s on
realistic Chinese** (i.e. ~6.5× faster than 1.2.0 on the same
hardware). Suddenly our 501 MB/s number looked completely different:
realistic Chinese was the workload that actually mattered, and we
were **0.50× of opencc 1.3.1**, not 1.29×.

This release ships the n-gram feature but **defers the perf work** —
the v0.7 → v0.8 split was chosen to keep ngram shippable without
regressing throughput. The perf patches land in v0.7.1 / v0.7.2 /
v0.7.3 / v0.7.4 / v0.7.5, closing the gap to **1.16× of opencc 1.3.1
on realistic + 7-12 % ahead on real corpora**.

## Bench (10 MB Chinese, Apple Silicon, release)

| mode      | MB/s    | × opencc 1.3.1 |
| --------- | ------: | -------------: |
| fast      | 28.5    | **0.50×** (loss) |
| bigram    | 21.7    | 0.33×          |
| trigram   | 21.5    | 0.33×          |
| opencc 1.3.1 | 65.7 | 1.00× (baseline) |

The 0.50× gap on `fast` is the v0.7.1+ perf patch target.

## Added

- **bigram / trigram disambig** via `NgramModel` + `NgramMode::{Bigram, Trigram}` (CLI flags `--bigram` / `--trigram` / `--fast`)
- **ARPA model loader** (`2gram.arpa` / `3gram.arpa`; not shipped — see ljh-sh/ngram-exp)
- **`Dict::longest_prefix_multi`** for the disambig path; default `Dict::longest_prefix` keeps the zero-alloc single-value path
- **Patch overlay** (`data/dictionary_patches/STPhrases.multi-value.tsv`) promotes single-value entries to multi-value without forking the upstream data directory
- **10 context regression tests** covering 齣/出 disambig + 2 known limitations + 1 custom-dict workaround

## Deferred to v0.7.1+ / v0.8

- `--report <PATH>` TSV sidecar (zhhz#15)
- `Converter::convert_with_report` / `scan_ambiguous`
- `AmbiguousDecision` struct
- All perf patches (land in v0.7.1 → v0.7.5)

## Compatibility

- Public API: `Converter::convert(&str) -> String` unchanged
- CLI: existing flags unchanged; new `--bigram` / `--trigram` / `--fast`
- Data: existing `data/dictionary/` unchanged; new `data/dictionary_patches/STPhrases.multi-value.tsv` overlay
- WASM build: unaffected
- Output byte-identical to v0.6.0 on every config both implement

## Install

```bash
cargo install zhhz --version 0.7.0
npm install zhhz@0.7.0
```
