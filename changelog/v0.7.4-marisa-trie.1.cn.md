# zhhz v0.7.4-marisa-trie.1

**状态：已搁置（SHELVED）。** 这是一个技术路线探索，**不是推荐版本**。
`release/v0.7.5` 上的 v0.7.5 是当前推荐版本。

## 这是什么

把 marisa-trie 的纯 Rust 移植
（[`rsmarisa`](https://crates.io/crates/rsmarisa)）作为 zhhz 的
**可选 feature flag**（`--features marisa`）集成进来。trie 只存
key（UTF-8 字节），value 保存在平行的 `Vec<Values>` 里，按
`agent.key().id()` 索引 —— 跟 OpenCC 用 marisa-trie 实现 `.ocd2`
的设计一样。

这是 Q/M/O 决策树（[zhhz#26](https://github.com/ljh-sh/zhhz/issues/26)）
中的 **O** 分支。

## Bench 结果（apples-to-apples，进程内 20 inner + 3 warmup）

| 语料 | v0.7.5（char-trie） | v0.7.4-marisa-trie.1 | Δ |
|--|--:|--:|--:|
| realistic-repeat fast | 75.17 | 73.12 | -2.7 % |
| realistic trigram | 33.59 | 32.66 | -2.8 % |
| classical fast | 41.26 | 41.00 | -0.6 % |
| classical trigram | 35.01 | 33.52 | -4.3 % |
| code fast | 67.83 | 68.16 | +0.5 % |
| news fast | 32.50 | 33.52 | +3.1 % |

没有稳定的胜出。在所有语料上都在 ±3 % 噪声范围内。

## 决策

**关闭，不合并到 main。** 完整决策记录见
[zhhz#33](https://github.com/ljh-sh/zhhz/issues/33)，
v0.7.x 性能故事见
[zhhz#34 retrospective](https://github.com/ljh-sh/zhhz/issues/34)。

基于 sample 的 profile（zhhz#32）显示 zhhz 在每个语料上**CPU 已经
比 opencc 快**（realistic-var 上 133 MB/s 对 opencc 的 67；
realistic-repeat 上 176 对 141）。wall 差距是 **cache miss +
allocator 压力**，不是 trie 结构。换成 marisa 哪个问题都修不了。

## 这个分支里有什么

- `src/dict_marisa.rs` — `MarisaDict`（190 行），实现和 `Dict` 一样的
  `longest_prefix` / `longest_prefix_multi` API。
- `Cargo.toml` — `rsmarisa = { version = "0.4.2", default-features = false, optional = true }`，
  `marisa = ["dep:rsmarisa"]` feature flag。
- `src/lib.rs` — feature flag 后的类型别名（feature 开启时 `Dict`
  是 `MarisaDict`）。
- `examples/perf_only.rs` — 进程内 zhhz convert timer。
- `scripts/bench-apples.sh` — apples-to-apples 跑分脚本。
- `scripts/bench-fast.sh` — 仅 fast 路径的跑分脚本（后加）。

## 构建 / 使用

```bash
# 不启用 marisa（默认 — 在 pinned toolchain 上能用）：
cargo build --release

# 启用 marisa（需要 rustc ≥ 1.86 支持 edition2024）：
cargo build --release --features marisa

# 跑分：
cargo run --release --example bench_perf
```
