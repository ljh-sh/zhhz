# zhhz v0.8.3

**CI / fuzzing surface upgrade.** No user-visible change to the Rust core,
npm tarball, or WASM API. Same 616 kB binary.

## Added

- `.github/workflows/fuzz.yml` — ASan + MSan matrix, both fuzz targets
  (`fmm_segment`, `convert_roundtrip`). 4-job matrix runs nightly at
  17:04 UTC, weekly backup at 00:04 UTC Sunday, and on `workflow_dispatch`.
- `oss-fuzz/` subtree (mirrors `google/oss-fuzz/projects/zhhz/`):
  - `project.yaml` — language: rust, sanitizers: address|memory|undefined
  - `Dockerfile` — `FROM gcr.io/oss-fuzz-base/base-builder-rust`
  - `build.sh` — builds each fuzz target with `$SANITIZER`, bundles seed corpus
- PR [google/oss-fuzz#16131](https://github.com/google/oss-fuzz/pull/16131)
  — submission awaiting Google review.
- `workflow_dispatch` input `max_total_time` on the Fuzz workflow, so
  longer runs (300s+) can be triggered on demand when chasing a repro.

## Fixed

- Fuzz workflow header check, license preamble, and project config
  schema to satisfy google/oss-fuzz's bot (`project.yaml` not
  `project.yml`; `auto_ccs` is a list of email strings).
- A longstanding MSan false-positive on `convert_roundtrip · memory`
  (zhhz#77) appears to have been triggered by a specific nightly build
  that is no longer the current one. Closed as not reproducible.
  Longer fuzz runs (PR #82) and unconditional crash artifact upload
  are now in place so the next finding is debuggable.

## Notes

- UBSan was dropped from the GH Actions matrix because rustc removed
  `-Z sanitizer=undefined` from its accepted values after nightly
  ~2024-11. UBSan will be added at the OSS-Fuzz layer where the
  base-builder image pins a toolchain that still supports it.
